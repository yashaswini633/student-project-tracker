# Student Project Tracker

A small full-stack web app for keeping track of electronics projects and their status.
You can add a project, edit its name or status, and delete it. Records are saved in a
SQLite database on the server, so they survive a browser refresh and a server restart.

Built as a workshop learning project. It runs locally only.

## Run

Use Node.js 22 (22.18 or newer, below 23; tested on 22.23.3) and a PowerShell terminal in this folder.

```powershell
npm.cmd ci
npm.cmd start
```

Open http://localhost:3000. Keep the server terminal running. Stop it with Ctrl+C.

On Node 22 the terminal prints `ExperimentalWarning: SQLite is an experimental feature`.
This is expected and is not an error.

To run the API test (it checks the API, not browser interactions):

```powershell
npm.cmd test
```

The test starts its own server on port 3198 with a temporary database, so it does not
change your saved projects.

## Files

| File | Role |
| --- | --- |
| `public/index.html` | Page structure: the form and the project list |
| `public/style.css` | Presentation, including the narrow-screen layout |
| `public/script.js` | Browser behaviour: reads the form, calls the API with `fetch`, draws the list |
| `server.js` | Starts the server on port 3000 |
| `app.js` | Express HTTP API: routes, input validation, error responses |
| `database.js` | Persistence: creates the table and runs the SQL against `data/projects.db` |
| `test/crud.test.js` | Automated API test for CRUD, validation and persistence |

## API

| Method | Path | Purpose | Success |
| --- | --- | --- | --- |
| GET | `/api/health` | Check the server is running | 200 |
| GET | `/api/projects` | List all projects | 200 |
| POST | `/api/projects` | Create a project | 201 |
| PUT | `/api/projects/:id` | Update a project | 200 |
| DELETE | `/api/projects/:id` | Delete a project | 200 |

A project has a `name` (1-80 characters) and a `status` of `Planned`, `In Progress` or
`Completed`. Invalid input returns 400 and an unknown id returns 404, each with a JSON
`error` message.

## How a request travels

Adding a project:

```text
Browser                                Server
-------                                ------
form submit
  -> script.js reads name and status
  -> fetch POST /api/projects  ----->  app.js validates name and status
                                         -> database.js runs INSERT with ? placeholders
                                         -> SQLite writes data/projects.db and creates the id
  <- 201 JSON { id, name, status } <---
  -> fetch GET /api/projects   ----->  database.js runs SELECT
  <- 200 JSON list             <-----
  -> script.js redraws the list
```

The id is generated by SQLite, not by the browser. Values typed by the user are passed
to the database separately from the SQL text.

## Evidence of testing

- `npm.cmd test`: 1 test, 1 pass, 0 fail (create, update, delete, validation, restart persistence, API errors).
- Browser, with DevTools Network open: add gave POST 201 then GET 200, edit gave PUT 200, delete gave DELETE 200.
- Editing a project kept the same id and did not create a duplicate.
- Cancelling a delete sent no request and kept the project.
- Projects were still present after a browser refresh and after stopping and restarting the server.
- A read-only query of `data/projects.db` showed the same rows as `GET /api/projects`.
- A blank or spaces-only name was rejected with "Enter a project name."
- With the server stopped, saving showed "Could not reach the server. Check that the server is running.",
  kept the typed name, and a retry after restarting saved exactly one record.
- With a slow connection, repeated clicks on Add Project sent only one POST.
- The page fits a 390px-wide screen without sideways scrolling.

## Limitations

- Local demo only; it is not hosted online. Cloud hosting would need separate server and database configuration.
- No login and no separate users: everyone using this server sees the same list.
- The database file `data/projects.db` stays on this computer and is not uploaded to GitHub.
- Projects saved by the earlier browser-storage version are not moved into the database.
